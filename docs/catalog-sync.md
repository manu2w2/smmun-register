# Plan de sincronización de Google Sheets a Supabase

La primera fase descarga el CSV y requiere confirmación manual. La automatización reutilizará la misma comparación y transacción en `catalog.import_representations`. Con la API de Sheets, se pueden transformar las celdas directamente al lote normalizado que usa el CSV.

1. **Configurar el origen por edición.** Registrar el ID del archivo y de la pestaña. La [hoja de prueba](https://docs.google.com/spreadsheets/d/1zO-z01dyBUPBbhA-eroPf6CL3YBk5cpRl-yYEkwNoCU/edit#gid=0) usa `catalogo` con `gid=0`. Resolver el título actual por ID y leer A:D con `spreadsheets.values.get` y `UNFORMATTED_VALUE`. Compartir solo el archivo necesario como lector con una cuenta de servicio dedicada y pedir el alcance `spreadsheets.readonly`. [Lectura de rangos](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get) · [Permisos de Sheets](https://developers.google.com/workspace/sheets/api/scopes)
2. **Validar y mostrar diferencias.** Verificar encabezados, tipos, filas incompletas y duplicados. Usar la misma normalización de texto del CSV y aceptar booleanos nativos además de las etiquetas admitidas. Preparar un resumen con el hash del contenido normalizado y los conteos del lote. Un error de lectura, una hoja vacía o filas ausentes requiere revisión. Un renombre se concilia conservando el UUID en PostgreSQL.
3. **Programar una función de servidor.** Empezar con Supabase Cron invocando una Edge Function autenticada. Guardar los secretos fuera del repositorio y usar un rol de base dedicado con acceso explícito a la función y a las columnas del catálogo necesarias para leer e importar. Reservar la escritura de `disponible` a la operación del catálogo. Permitir una sola corrida por edición desde la lectura de Sheets hasta la aplicación, y pausar el horario antes de una carga manual. PostgreSQL vuelve a calcular las diferencias al aplicar y serializa las escrituras de cada edición. [Supabase Cron](https://supabase.com/docs/guides/cron) · [Seguridad de la API](https://supabase.com/docs/guides/api/securing-your-api)
4. **Probar primero en staging.** Ejecutar en vista previa con datos sintéticos, luego habilitar altas y cambios sin ausencias. Registrar por corrida edición, hora, hash, conteos y resultado, sin el contenido de la hoja ni credenciales. Reintentar fallos transitorios con espera creciente y alertar si falla la validación o aparece una ausencia. Verificar que un lote repetido conserva UUID y disponibilidad, que las corridas simultáneas no duplican filas y que una caída de Google deja el catálogo anterior utilizable.
5. **Operar y recuperar.** Acordar con el equipo el intervalo y el responsable de las alertas antes de activar el horario. Para pausar, desactivar el trabajo programado y volver a la revisión manual por CSV. Aplicar correcciones como lotes revisados, conservando disponibilidad y los identificadores existentes.
